**Rehearsal, 20 Oct 2026.** A fresh PostgreSQL 16 was set up like a managed host (the owner is neither superuser nor allowed to bypass row-level security). The run had no `.env` file and only the settings `render.yaml` provides, including a generated password containing `+` and `/`. Results:

- The first deploy created the app user.
- The app connected only as that user.
- The first administrator was created, sign-in worked, and MFA was enforced.
- The daily job ran.
- The fictional data loaded with the isolation rules on: a technician opened a device, and the other organisation got "not found".
- A second deploy changed nothing.
- A wrong password stopped the deploy cleanly.
- Not rehearsed: Prisma applying migrations on Render itself. This workspace cannot download its migration engine.
